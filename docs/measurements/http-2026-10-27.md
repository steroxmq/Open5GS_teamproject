### Zdroje a hranice interpretacie

Kazda skupina ma 21 vzoriek hostitela VM, spolu 189. CPU busy, minimum
MemAvailable a maximum pouziteho swapu boli overene zo surovych /proc dat.
CPU busy je rozdiel pocitadiel bez idle a iowait, vratane steal a bez
dvojiteho zapocitania guest. Dostupna RAM neklesla pod 1 848 860 KiB;
maximum pouziteho swapu bolo 1 004 480 KiB. Ide o vzorky VM pocas HTTP,
nie o kontajnerove metriky alebo maxima pocas celej 16-sekundovej zataze.

V tejto serii maju UL aj DL vyssi median a p95 nez idle. p95 je najvyssie
pri DL, hoci median je vyssi pri UL. Skupiny boli vykonane v pevnom poradi
idle -> UL -> DL, iba s tromi opakovaniami a 60 poziadavkami na podmienku.
CPU VM kolisal, najma pri UL-3. Tieto pozorovania neopravnuju pripisat
cely rozdiel sietovemu radeniu, tvrdit statisticku vyznamnost ani urcit
vseobecne horsi smer. Bez riadenej zataze znamena bez pridaneho iperf3,
nie nevyhnutne bez inej aktivity VM. Skutocne intervaly zaciatkov HTTP
boli 0.3644 az 0.4259 s pri planovanom intervale 0.4 s.

TCP 50 Mbit/s je riadena zataz, nie maximalna kapacita siete. Pilot bezi
na spolocnej Docker sieti, nie na izolovanej N6 ani v realnom MEC.
UERANSIM nenahradza skutocnu radiovu vrstvu. Historicky pilot a loopback
vyssie nie su zahrnute do 180 novych HTTP poziadaviek ani do TCP statistik.

## Parametre a postup serie

Z korena projektu v terminali s pristupom k Docker a root namespace:

```bash
sudo python3 scripts/check-edge.py
sudo python3 scripts/measure-http.py
```

Ak pilot zlyha, najprv oddelit ping UE -> UPF od kontroly UPF -> edge
`/health` a ulozit diagnostiku. `compose-up.sh` pouzit iba pri potvrdenej
poruche UE a mimo merania; obnovuje gNB a UE. Nespustat reset ucastnika,
MongoDB ani nove zostavovanie obrazov.

Parametre vykonanej serie: idle, TCP UL a TCP DL; tri opakovania kazdej skupiny,
20 HTTP poziadaviek na opakovanie, interval zaciatkov 0.4 s, zataz 16 s
s cielom 50 Mbit/s. Spolu 180 planovanych poziadaviek. Kazda odpoved
musi potvrdit obsah, request_id, adresu UE a NAT zdroj UPF. Prekryv sa
overuje konzervativnym oknom z monotonneho zivota klienta a suvislych
nenulovych datovych intervalov. Cas HTTP nie je ciste sietove RTT.

Pri opakovani novy beh vytvori vlastny adresar `results/http-*` so surovymi datami,
CSV, `summary.json` a `report.md`. Az skutocne dokonceny a overeny beh
moze mat stav complete. TCP ciel 50 Mbit/s nepredstavuje maximalnu kapacitu.
