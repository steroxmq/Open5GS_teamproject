## Parametre a postup serie

Z korena projektu v terminali s pristupom k Docker a root namespace:

```bash
sudo python3 scripts/check-edge.py
sudo python3 scripts/measure-http.py
```

Ak pilot zlyha, najprv oddelit ping UE -> UPF od kontroly UPF -> edge
`/health` a ulozit diagnostiku. `compose-up.sh` pouzit iba pri potvrdenej
poruche UE a mimo merania; obnovuje gNB a UE. Nespustat reset ucastnika,
MongoDB ani nove zostavovanie obrazov.

Plan serie: idle, TCP UL a TCP DL; tri opakovania kazdej skupiny,
20 HTTP poziadaviek na opakovanie, interval zaciatkov 0.4 s, zataz 16 s
s cielom 50 Mbit/s. Spolu 180 planovanych poziadaviek. Kazda odpoved
musi potvrdit obsah, request_id, adresu UE a NAT zdroj UPF. Prekryv sa
overuje konzervativnym oknom z monotonneho zivota klienta a suvislych
nenulovych datovych intervalov. Cas HTTP nie je ciste sietove RTT.

Novy beh vytvori vlastny adresar `results/http-*` so surovymi datami,
CSV, `summary.json` a `report.md`. Az skutocne dokonceny a overeny beh
moze mat stav complete. TCP ciel 50 Mbit/s nepredstavuje maximalnu kapacitu.
