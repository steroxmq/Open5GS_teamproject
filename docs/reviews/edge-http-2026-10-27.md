## Podstatne nalezy a opravy

1. **Vysoka priorita: SIGTERM pilota neobnovil trasu.** `check-edge.py`
   mal predvolenu obsluhu SIGTERM, ktora obisla finally. Teraz signal
   vyvola riadeny neuspech, obnovu vlastnej trasy a zapis reportu.
   Pocas obnovy sa dalsie SIGINT/SIGTERM ignoruju. Test posiela skutocny
   SIGTERM procesu testu pri simulovanom HTTP a overuje aj zachovanie
   predexistujucej trasy.
2. **Stredna priorita: prerusenie HTTP cakalo na celu TCP zataz.**
   ThreadPoolExecutor cakal na nezrusenu ulohu. Teraz sa pri odchode
   zo skupiny nastavi cancel_event. Prikazy zataze sleduju zrusenie,
   ukoncia vlastnu procesovu skupinu a pockaju na procesy; server sa
   cisti vo finally. Test overuje aj ukoncenie potomka, nie iba rodica.
3. **Stredna priorita: odmietnute pridanie trasy spustilo mazanie.**
   Priznak vlastnictva sa nastavoval pred add a ostal aktivny aj po
   jednoznacnom odmietnuti. To mohlo odstranit trasu pridanu inym procesom.
   Teraz sa po jednoznacnej chybe add nemaze; timeout zostava neistym
   pripadom s pokusom o obnovu. Testy overuju odmietnute add, existujucu
   trasu aj failed pri chybe mazania.
4. **Stredna priorita: prekryv toleroval male medzery v intervaloch.**
   Tolerancia 0.01 s na kazdej hranici mohla povazovat roztrhnute
   intervaly za suvisle. Teraz je tolerancia iba 1e-6 s a odmietaju sa
   nekonecne/NaN alebo logicke pocty bajtov a neplatne hranice.
5. **Stredna priorita: neplatny cas HTTP mohol vstupit do statistik.**
   Validacia teraz odmieta nekonecne, NaN, zaporne, logicke a necislicove
   trvania. Nulova zaokruhlena hodnota zostava pripustna. Median a p95
   sa inak pocitali spravne: median standardne, p95 nearest rank.
6. **Dokumentacia a cerstvy klon.** Prevzate boli aktualizovane kroky
   README z origin/main so zachovanim HTTP casti. HTTP navod explicitne
   uvadza hostitelske nastroje, izolovany iperf3 3.21 a pouziva spolocny
   flock aj pri spusteni edge. Zastarale tvrdenie o neoverenej UE serii
   bolo nahradene skutocnym zaznamom 180/180. Lokalne suroviny nie su
   sucastou klonu a nie su predpokladom noveho merania.

## Posudene dokazovanie

HTTP klient viaze socket cez SO_BINDTODEVICE na uesimtun0 aj na dynamicku
adresu UE. Kontroluje sa trasa, zdroj po NAT na UPF, HTTP 201, jedinecny
request_id a obsah odpovede. Priama cesta cez Docker eth0 sa nepovazuje
za uspech. Zdrojova IP je diagnostika cesty, nie autentifikacia.

Prekryv pouziva suvisle nenulove intervaly iperf3 a monotonne casy zivota
klienta P0/P1. Pre datovu fazu dlzky D lezi garantovane okno v
[P1-D+0.1, P0+D-0.1]. Cely HTTP pokus sa musi zmestit do okna.
Samotne cakanie 3 s, zivy proces ani timestamp pred riadiacou vymenou
nie su dokazom prekryvu. Klient aj server musia uspesne dokoncit meranie.

Neuspech, prerusenie alebo chyba obnovy nevedu k complete. Uz vykonane
HTTP pokusy zostavaju v JSONL a CSV aj pri chybe zataze; suhrn obsahuje
uspesnost a statistiky iba uspesnych odpovedi. Vsetky operacie merania
a start labu zdielaju results/.compose-up.lock.
